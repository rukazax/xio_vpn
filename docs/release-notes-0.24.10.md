# XIO 0.24.10 — при поднятом туннеле нельзя менять не только режим

Уточнение к 0.24.9, выпущенное через час после неё: поведение то же, изменена
формулировка одного сообщения.

## Что исправлено

- 0.24.9 на живом туннеле писала: «Туннель активен. Сначала отключите VPN: пока
  соединение поднято, режим менять нельзя.» Это правда, но не вся правда: форма
  настроек соединения целиком плановая — проверка сайта, адрес проверки, таймаут,
  переподключение и режим попадают в план и receipt, поэтому при поднятом
  туннеле неактивна и кнопка «Сохранить», а не только переключатель режима
  (`workspace_ui.dart`, `client_main.dart`: «every connection setting in this
  form is plan-sensitive, so the Store's idle-only admission applies to the save
  button as a whole»).
- Новый текст: «Туннель активен. Сначала отключите VPN: пока соединение
  поднято, настройки соединения менять нельзя.» Переведён на все 13 языков.
- Логика не менялась: тот же код отказа `connected`, нативной стороне тот же
  `POLICY_BUSY`. Адресное послабление («пусть сохраняются настройки, не
  затрагивающие режим») не делалось: все поля формы плановые по построению, и
  менять это ради одного экрана — отдельная работа, а не формулировка текста.

## Проверено на телефоне 23122PCD1G (0.24.10+5027, выпускная сборка)

| Сценарий | Что на экране |
|---|---|
| Подключено, «Настройка соединений» | «Туннель активен. Сначала отключите VPN: пока соединение поднято, настройки соединения менять нельзя.»; «Сохранить» неактивна даже после смены таймаута |
| «Отключиться» → «Настройка соединений» | блокера нет, форма сохраняется, «Подтверждённый режим» совпадает с выбором |
