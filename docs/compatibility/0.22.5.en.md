# XIO Client 0.22.5: compatibility and status

Prerelease 0.22.5+5014. Compared to 0.22.4 it fixes two defects and adds a native Windows check.

## Protocols

| Platform | Native engines by source | Missing | 0.22.5 status |
|---|---|---|---|
| Android 8+ | AWG, RIVET/H3, RIVET/S1, Xray/REALITY, OpenVPN/Cloak | — | signed ARM32, ARM64, x86-64 and universal |
| Windows x64 | AWG, RIVET/H3, RIVET/S1, Xray/REALITY | OpenVPN/Cloak | **native tunnel verified** (Wintun); Xray does not connect |
| Ubuntu x64 | AWG, RIVET/H3, RIVET/S1, Xray/REALITY | OpenVPN/Cloak | build available, no 0.22.5 network run |
| iOS | RIVET/H3, RIVET/S1 | AWG, Xray/REALITY, OpenVPN/Cloak | sources prepared only; no IPA |

Full five-protocol compatibility is not achieved. `python3 tools/check-protocol-parity.py
--require-complete` still exits with code 2: desktop lacks Cloak, iOS lacks three engines.

## Verified on 0.22.5

- Windows x64, AmneziaWG: connects to the test server, `xio019` adapter with `10.78.0.7/32`, `ping`
  to the tunnel gateway 3/3, traffic exchanged (496 KB in, 2.9 MB out), clean disconnect. This is the
  first native Windows engine check rather than a cross-build.
- Android, AmneziaWG: IPv4 and IPv6 endpoints, HTTPS check inside the tunnel.
- Android, RIVET/H3 and S1: connection and traffic.
- Android, Xray/REALITY: **does not connect**. The Xray 26.7.28 server logs
  `REALITY: processed invalid connection`; the client core is the `amnezia-xray-core v1.260728.0`
  fork. Keys, `shortId` and `serverName` match, and lowering `minClientVer` does not help.

## Remaining limits

1. Public IPv6 is unverified. The test stand uses a local ULA `fd88:17::/64`; IPv6 egress from the
   tunnel is blocked by the server (`ip6tables FORWARD ... -j DROP`) and there is no NAT66.
2. Desktop still requires an IPv4 endpoint in some paths; the IPv6 endpoint was verified on Android.
3. Running alongside another VPN on the same machine is not supported: with a foreign VPN holding
   `/1` routes the tunnel comes up but the handshake never completes.
4. No iOS build: no Mac/Xcode/iPhone.

## Fixes

- Re-importing an `xio://` profile after deletion is no longer blocked.
- Windows: the IPv6 block rule uses `::/1,8000::/1`, because netsh rejects `::/0`.
