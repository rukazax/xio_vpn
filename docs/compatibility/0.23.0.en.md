# Compatibility 0.23.0

Date: 2026-10-26. Build: **0.23.0+5015**. What was verified, when and how — not "✅ by declaration".

## What changed in 0.23.0

- end-to-end rename `x1o` → `XIO`: packages `app.xio.client`/`app.xio.xio`, Dart package `xio`, server paths
  `xio-managed`/`/etc/xio`, server interfaces `xio0`/`xioawg0`. **The client helper still creates device
  `xio019`** — that name did not change;
- profile re-import after deletion fixed (deleting a profile no longer leaves a dangling user reference);
- Windows IPv6 firewall rule added as `remoteip=::/1,8000::/1` (netsh rejects `::/0`);
- a separate install is not required: `app.xio.client` has existed since 0.22.4 and Android updates in place;
- built: Android (4 client APKs + 4 full-app APKs), Windows (2 ZIPs), Ubuntu (client `.deb` and `.tar.gz`,
  full app `.tar.gz`); **iOS not built**;
- hashes of every release file and their device linkage are in
  [`verification-0.23.0.json`](https://github.com/rukazax/xio_vpn/releases/download/v0.23.0/verification-0.23.0.json).

## Not verified

- the full "5 transports × 3 platforms" matrix on 0.23.0: only AWG was exercised on Android and Ubuntu;
- RIVET/H3 and S1 through the 0.23.0 client (last run — Android 2026-10-26 on 0.22.4);
- public IPv6 (the stand has only a local ULA prefix, IPv6 egress is blocked by the server on purpose);
- iOS: no Mac/Xcode/iPhone, no IPA;
- Windows: connect is blocked by a firewall-setup defect — a product defect, not a stand issue.

## Known limitations

- **Xray/REALITY does not connect** on the "0.23.0 client + Xray 26.7.28 gateway" pair.
- **Windows**: `Windows VPN firewall setup failed` — the helper runs elevated, the server handshake succeeds,
  `netsh` inside the helper returns an error while the same command run manually succeeds.
- **Ubuntu**: the GUI client does not create a window (Impeller/EGL); the tunnel works through
  `libexec/xio-tunnel` and requires `systemd-resolved`.
- **A full tunnel on Linux** cuts off the LAN: while the tunnel is up the machine does not answer SSH from the
  local network.
