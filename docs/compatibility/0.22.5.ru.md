# XIO Client 0.22.5: совместимость и состояние

Предварительный выпуск, 0.22.5+5014. Относительно 0.22.4 исправлены два дефекта и добавлена
нативная проверка Windows.

## Протоколы

| Платформа | Нативные движки по исходникам | Отсутствуют | Состояние 0.22.5 |
|---|---|---|---|
| Android 8+ | AWG, RIVET/H3, RIVET/S1, Xray/REALITY, OpenVPN/Cloak | — | подписанные ARM32, ARM64, x86-64 и universal |
| Windows x64 | AWG, RIVET/H3, RIVET/S1, Xray/REALITY | OpenVPN/Cloak | **нативный туннель проверен** (Wintun); Xray не подключается |
| Ubuntu x64 | AWG, RIVET/H3, RIVET/S1, Xray/REALITY | OpenVPN/Cloak | сборка есть, сетевой прогон 0.22.5 не выполнялся |
| iOS | RIVET/H3, RIVET/S1 | AWG, Xray/REALITY, OpenVPN/Cloak | только подготовка исходников; IPA нет |

Полной пятипротокольной совместимости нет. `python3 tools/check-protocol-parity.py --require-complete`
по-прежнему возвращает код 2: desktop без Cloak, iOS без трёх движков.

## Что проверено на 0.22.5

- Windows x64, AmneziaWG: подключение к тестовому серверу, адаптер `xio019`, адрес `10.78.0.7/32`,
  `ping` до шлюза туннеля 3/3, обмен трафиком (496 КБ принято, 2.9 МБ передано), корректное
  отключение. Это первая нативная проверка Windows-движка, а не cross-build.
- Android, AmneziaWG: IPv4- и IPv6-endpoint, HTTP-проверка внутри туннеля.
- Android, RIVET/H3 и S1: подключение и трафик.
- Android, Xray/REALITY: **не подключается**. Сервер Xray 26.7.28 отвечает
  `REALITY: processed invalid connection`, клиентское ядро — форк `amnezia-xray-core v1.260728.0`.
  Ключи, `shortId` и `serverName` совпадают, понижение `minClientVer` не помогает.

## Ограничения, которые сохраняются

1. Публичный IPv6 не проверен. Тестовый стенд использует локальный ULA `fd88:17::/64`; выход
   IPv6 из туннеля блокируется сервером (`ip6tables FORWARD ... -j DROP`), NAT66 отсутствует.
2. Desktop по-прежнему требует IPv4-endpoint для части сценариев; IPv6-endpoint проверен на Android.
3. Одновременная работа с другим VPN на той же машине не поддерживается: при активном стороннем
   VPN с маршрутами `/1` туннель поднимается, но рукопожатие не завершается.
4. iOS не собран: нет Mac/Xcode/iPhone.

## Исправления

- Повторный импорт `xio://` профиля после удаления больше не блокируется.
- Windows: правило блокировки IPv6 ставится через `::/1,8000::/1` — netsh не принимает `::/0`.
