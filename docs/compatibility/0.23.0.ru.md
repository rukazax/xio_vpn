# Совместимость 0.23.0

Дата: 26.10.2026. Сборка: **0.23.0+5015**. Ниже — что именно проверено, когда и чем, без «✅ по декларации».

## Что изменилось в 0.23.0

- сквозное переименование `x1o` → `XIO`: пакеты `app.xio.client`/`app.xio.xio`, Dart-пакет `xio`, серверные
  пути `xio-managed`/`/etc/xio`, серверные интерфейсы `xio0`/`xioawg0`. **Клиентский помощник по-прежнему
  поднимает устройство `xio019`** — это имя не менялось;
- исправлен повторный импорт профиля после удаления (удаление больше не оставляет висячую ссылку пользователя);
- на Windows добавлено правило IPv6-firewall `remoteip=::/1,8000::/1` (прежняя форма `::/0` не принимается netsh);
- отдельная установка не требуется: `app.xio.client` существует с 0.22.4, Android обновляет приложение поверх;
- собраны Android (4 APK клиента + 4 APK полного приложения), Windows (2 ZIP), Ubuntu (клиент `.deb` и
  `.tar.gz`, полное приложение `.tar.gz`); **iOS не собран**;
- хеши всех файлов релиза и привязка к устройствам — в
  [`verification-0.23.0.json`](https://github.com/rukazax/xio_vpn/releases/download/v0.23.0/verification-0.23.0.json).

## Что не проверено

- полная матрица «5 транспортов × 3 платформы» на 0.23.0: проверены AWG на Android и Ubuntu, остальное —
  по артефактам предыдущих версий;
- RIVET/H3 и S1 через клиент 0.23.0 (в 0.23.0 не прогонялись; последний прогон — Android 2026-10-26 на 0.22.4);
- публичный IPv6 (на стенде только локальный ULA, выход IPv6 сервер блокирует намеренно);
- iOS: нет Mac/Xcode/iPhone, IPA отсутствует;
- Windows: подключение заблокировано дефектом настройки firewall — это дефект продукта, а не стенда.

## Известные ограничения

- **Xray/REALITY не подключается** на паре «клиент 0.23.0 + шлюз Xray 26.7.28».
- **Windows**: `Windows VPN firewall setup failed` — помощник запущен с правами администратора, handshake до
  сервера доходит, `netsh` внутри помощника возвращает ошибку; та же команда вручную выполняется успешно.
- **Ubuntu**: GUI-клиент не создаёт окно (Impeller/EGL); туннель работает через `libexec/xio-tunnel` и требует
  `systemd-resolved`.
- **Полный туннель на Linux** отрезает LAN: пока туннель поднят, машина не отвечает по SSH из локальной сети.
