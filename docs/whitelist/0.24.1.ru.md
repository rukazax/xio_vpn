# Каталог «белых» SNI (0.24.1)

RU: операторы мобильной связи в России фильтруют трафик по имени в TLS (SNI). Если имя входа
XIO входит в разрешённый список оператора, рукопожатие проходит; если нет — соединение рвётся или
уходит в таймаут. Каталог отвечает на один вопрос: **какие имена из публичного белого списка годятся
как внешний SNI именно с этого сервера**.

## Что делает каталог

1. Скачивает список с запиненного адреса (`server/catalog/whitelist-pins.json`), сверяет `sha256`
   и не принимает подменённый или обрезанный файл.
2. Приводит имена к ASCII/IDNA, отбрасывает wildcard, порты, пробелы и дубликаты.
3. Проверяет каждое имя **с самого сервера**, мимо туннеля: DNS → TCP 443 → сертификат (срок и
   покрытие имени) → **TLS 1.3** (REALITY без него не работает).
4. Пишет `whitelist-<YYYYMMDD>.json` атомарно, с `contentSha256` по `(fqdn, eligible, resolved)`,
   провенансом источника и копией предыдущей версии для отката.

Причины отказа видны в артефакте: `invalidEntry`, `unresolved`, `unreachable`, `certInvalid`,
`certMismatch`, `tls12Only`.

## Как включить

Каталог входит в серверный пакет 0.24.1 (`xio-server-0.24.1.tar.gz`) и обновляется еженедельным таймером
`xio-catalog.timer` (`OnCalendar=weekly`, `RandomizedDelaySec=30min`).

```sh
systemctl list-timers xio-catalog.timer
systemctl start xio-catalog.service      # первый прогон, если не хотите ждать неделю
python3 /usr/local/lib/xio-managed/catalog/lint_catalog.py --file /var/lib/xio-catalog/whitelist-<дата>.json
```

Забрать список администратору:

```sh
printf '%s\n' '{"action":"catalog","serverId":"<id>"}' | python3 /usr/local/lib/xio-managed/admin.py
```

## Что каталог не делает

- **Не маршрутизирует по домену.** Клиентский split-routing принимает только IP/CIDR.
- **Не применяет маску сам.** Выбор имени — явное действие администратора; каталог ничего не меняет
  в профилях и в конфигурации сервера.
- **Не помогает при модели `ip+sni`.** Если оператор сверяет и IP, подмена SNI бесполезна: нужен
  вход на адрес из белого списка (отдельный релей), это инфраструктурное решение владельца.

Живая сеть недетерминирована: два прогона подряд дают разные `unreachable`/`tls12Only`. Поэтому
гарантия детерминизма сформулирована на **фиксированном входе проб** (`tools/test_catalog_determinism.py`),
а не на живом прогоне.

## EN

Mobile operators in Russia filter by TLS SNI. If the XIO entry name is on the operator allow list the
handshake succeeds; otherwise the connection is reset or times out. The catalog answers one question:
which names from the public allow list are usable as an outer SNI **from this server**.

It downloads the pinned list, verifies its `sha256`, normalises names to ASCII/IDNA, probes each name
from the server itself (DNS → TCP 443 → certificate validity and coverage → TLS 1.3 required by
REALITY) and writes a deterministic artifact with provenance and a previous-version copy.

It does not route by domain (client split-routing accepts IP/CIDR only), does not apply a mask on its
own (choosing a name stays an explicit administrator action) and does not defeat `ip+sni` filtering —
that needs an ingress on a whitelisted address.
