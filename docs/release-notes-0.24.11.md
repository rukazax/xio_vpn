# XIO 0.24.11 — APK ставится и работает, логи выключены

Выпуск про две вещи, которые важнее новых функций: установка и тишина.

## 1. Почему 0.24.10 не устанавливалась

Релиз 0.24.10 собирался одной fat-сборкой на 75 МБ и выкладывался под двумя
именами. Внутри файла, названного `armeabi-v7a`, движок Flutter был только
32-битный, а каталоги `lib/arm64-v8a` (`libgojni.so`, `libc++_shared.so`,
`libxio_openvpn.so`) тоже присутствовали. Android выбирал `primaryCpuAbi=arm64`
по этим библиотекам, не находил 64-битные `libflutter.so` и `libapp.so` — и
приложение устанавливалось, но при запуске сразу закрывалось. Воспроизведено на
тестовом телефоне: процесс `app.xio.xio` живёт, активити не появляется.

Теперь каждый APK собирается отдельно и содержит библиотеки только своей ABI:

| Файл | ABI внутри | Размер |
|---|---|---|
| `XIO-Full-0.24.11-android-arm64-v8a.apk` | только `lib/arm64-v8a` | 52,4 МБ |
| `XIO-Full-0.24.11-android-armeabi-v7a.apk` | только `lib/armeabi-v7a` | 52,3 МБ |

`versionCode` у обоих 5028 (`-P force-version-code-ignoring-abi=true`), чтобы
обновление с 0.24.10 и апдейтер видели одну версию, а не разные номера под ABI.

## 2. Логирование и телеметрия выключены

- `XioDiag.log` в релизе — пустая операция: нет ни файла, ни буфера, ни вызова
  нативной стороны.
- Kotlin `Diag` в релизе не создаёт каталог журнала, не пишет файл, не ставит
  crash-handler и не читает logcat.
- Все `android.util.Log` в коде приложения заменены на `XLog`, который пишет
  только в тестовой сборке.
- Удалён geo-IP запрос к `ipapi.co`: страна берётся только из данных на
  устройстве. Обновлены правовые тексты и `assets/help/privacy.*`.
- Остались вызовы только по действию пользователя: «Проверить каскад», проверка
  соединения (по умолчанию выключена) и проверка обновлений.

Тестовая сборка (`-PxioTestBuild=true`) сохраняет всё как раньше: журнал,
bundle, выгрузку в панель.
