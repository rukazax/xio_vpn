### «Очистить сервер»

Пункт есть в меню сервера, в настройках серверов и в диалоге подключения.

- Удаляет всё, что принадлежит XIO: службы, профили, RIVET, каскад, панель,
  ключи каскада, правила XIO, журнал установки XIO, `tun0` (только если он
  держит каскадный `/30`).
- Работает и на сервере **без** установленного XIO: bootstrap-маркер создаётся
  при необходимости — это и есть «очистка перед установкой».
- Сервер сам возвращает `removed`/`remaining`; непустой `remaining` — ошибка,
  а не «сервер очищен».
- Общие пакеты ОС, чужие службы, чужие туннели, чужие правила firewall и
  системный журнал не затрагиваются. Конфигурация nginx хоста (vhost домена)
  тоже остаётся: это файл администратора, а не XIO.

### Ограничение, которое нельзя обойти изнутри

BBR на exit включить нельзя: это LXC, ядро общее с хостом Proxmox, а модуля
`tcp_bbr` в контейнере нет. BBR работает на bridge — там, где TCP-туннель
bridge → exit действительно завершается. На exit остаётся `cubic`.

### Транспорты в каскаде: найденный разрыв и что сделано

Правило каскада было `iif xioawg0` — то есть в туннель уходил **только
AmneziaWG**. У Xray и у RIVET-gateway нет входного интерфейса: они завершают
соединение сами и открывают исходящие с bridge, поэтому их трафик шёл напрямую
из РФ.

- В `xio-cascade-bridge-up.sh` (и в том же скрипте внутри приложения) добавлены
  `ip rule add fwmark ${XIO_CASCADE_MARK:-0x518} lookup 51888` и SNAT
  `-o tun0 -j MASQUERADE` для локально созданного трафика; в `-down.sh` —
  симметричное удаление.
- Проверено: без правила помеченный сокет выходил `81.177.142.37`, после —
  `103.102.135.124` при неизменном прямом выходе bridge.
- **Что ещё не сделано:** Xray и RIVET должны сами ставить метку на свои
  исходящие сокеты (`sockopt.mark` у Xray, соответствующая опция у RIVET
  gateway). Пока метка не выставлена, их трафик по-прежнему выходит из РФ.
  Это следующий шаг, а не выполненная работа.

### Что помешало и как обходили

1. **После обновления приложение не смогло подключиться**:
   «The saved plan could not be reconciled with the local engine». Ни retry в
   экране маршрутизации, ни перезапуск не помогли; помогло только
   `pm clear app.xio.xio`. Профиль после этого импортирован заново из
   конфигурации, выданной сервером (`/sdcard/Download/xio-awg-phone.conf`).
   Это дефект восстановления состояния, а не следствие новых функций: он
   воспроизводится на паре 0.24.3 → 0.24.4 при отключении VPN перед обновлением.
2. **Системный файловый диалог** (`Файл с настройками подключения`) в
   adb-режиме отдаёт пустой список, поэтому конфигурация вставлялась через
   диалог «Вставить ключ или конфигурацию».
3. **Скриншоты приложения недоступны**: включён `FLAG_SECURE`, а переключатель
   «Разрешить скриншоты» отвечает «Сохранение разрешения не подтверждено».
   Интерфейс проверялся по дереву доступности (`uiautomator dump`), не по
   изображению.
4. **Адреса каскада не сохранились** через диалог «Серверы каскада»: кнопка
   «Сохранить» не закрывает диалог. Пункт нужно починить отдельно.

### Что осталось непроверенным

- Xray и RIVET из приложения через каскад: профили этих транспортов выдаются
  только управляемому серверу, а после сброса данных приложение пришлось
  поднимать импортом одного AWG-конфига. Проверен путь выхода (метка), но не
  сами клиентские подключения.
