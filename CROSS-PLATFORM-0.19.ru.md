# XIO 0.19 — клиенты Ubuntu, Windows и проект iPhone/iPad

Правообладатель собственного кода: Ерёмин Константин Александрович, er-ka@mail.ru. Лицензия собственного кода GPL-3.0-only. Выпуск 0.18 Android сохраняется отдельно; его APK и серверный пакет не заменяются этим выпуском.

## Состав и границы переноса

| Платформа | Результат | Движки в этой версии |
|---|---|---|
| Ubuntu x86_64, 22.04+ | DEB и переносимый архив; выпуск для испытаний | WireGuard, AmneziaWG, RIVET/H3, RIVET/S1, Xray, Shadowsocks, Tailscale/Headscale |
| Windows 10/11 x64 | переносимый ZIP с настоящим Flutter AOT exe; кандидат для испытаний | те же 7 движков с Wintun; драйвер, UAC и маршруты ещё требуют проверки в настоящей Windows |
| iPhone/iPad, iOS 15+ | исходники Xcode-проекта и скрипт сборки; IPA отсутствует | подготовлена интеграция RIVET/H3 и RIVET/S1; требуется Mac/Xcode, подпись, сборка и испытание NetworkExtension на устройстве |

OpenVPN, OpenVPN/Cloak и IKEv2 из Android ещё не реализованы в настольном помощнике. Они сохраняются при переносе полного пользовательского профиля, но не участвуют в автоматическом выборе на этой платформе. iOS не объявляется эквивалентом Android по набору протоколов. Приложение не сертифицировано и не прошло независимый аудит; обещание обхода любых блокировок отсутствует.

Общие экраны, 13 языков, темы, пользователи, импорт/экспорт профилей, настройки соединения и управление VPS используют существующий Flutter-код. Маршрутизация по приложениям из Android не переносится автоматически на Windows/Linux/iOS. Не все функции Android имеют нативный эквивалент в этом выпуске.

## Ubuntu

Установка: `sudo apt install ./XIO-0.19.0-ubuntu-amd64.deb`, затем запуск XIO из меню приложений или командой `xio`. Обычный интерфейс запускается от вашего пользователя. При подключении `pkexec` запрашивает разрешение на запуск отдельного сетевого помощника. Не запускайте весь интерфейс через sudo.

Для переносимого архива распакуйте каталог XIO целиком и запустите `./XIO/XIO`. Нужны GTK3, iproute2, pkexec/polkit и работающий systemd-resolved. При отсутствии polkit-агента в графическом сеансе системный запрос пароля может не появиться; используйте обычный сеанс Ubuntu Desktop.

Нажмите «+», вставьте профиль/конфигурацию либо подключите свой VPS по SSH. Существующий серверный пакет предназначен для amd64 VPS с systemd и TUN; архитектура ПК и архитектура сервера — разные требования. Поддержка произвольного ARM VPS не заявляется.

Выберите сервер. В настройках соединения задайте проверочный HTTPS-сайт и приоритет протокола. По умолчанию остаётся youtube.com. Если сайт недоступен с VPS, автоматическая проверка может отклонить рабочий туннель; для диагностики задайте https://example.com. На испытательном VPS YouTube не разрешался и без VPN-клиента, что записано в отчёте.

## Windows

Распакуйте ZIP целиком в свой каталог и запустите `XIO.exe`. Каталоги data и libexec обязательны. Интерфейс работает без повышения прав, отдельное подтверждение UAC нужно при запуске сетевого помощника. В libexec находится исходная официальная amd64 wintun.dll, используемая через публичный API Wintun. Этот драйвер имеет отдельные условия в WINTUN-LICENSE.txt и не переименован в компонент под GPL.

Exe XIO и сетевой помощник не подписаны сертификатом издателя. Нативная установка драйвера и подтверждение UAC на Windows ещё не проверены; этот ZIP следует сначала испытать на тестовом Windows-компьютере. Проверки Wine не заменяют эти испытания.

SSH-пароли и профили шифруются Windows DPAPI CurrentUser. Они не должны автоматически переноситься копированием внутреннего каталога на другую учётную запись: используйте явный экспорт профиля/сервера. Экспорт административной конфигурации передаёт секреты и должен храниться как пароль.

## iPhone и iPad

На этой машине нет подключённого Mac и настроенной команды Apple Developer. Готового подписанного IPA здесь нет. ZIP с iOS содержит проект и исходники, а не устанавливаемое приложение.

На Mac зарегистрируйте App IDs `app.xio.client` и `app.xio.client.PacketTunnel`, capability Packet Tunnel Provider, app group `group.app.xio.client`, общую keychain group. Войдите в Xcode своей командой. При необходимости измените занятые идентификаторы согласованно во всех файлах проекта.

Передайте `XIO_APPLE_TEAM_ID` и абсолютный путь `XIO_IOS_EXPORT_OPTIONS` к своему ExportOptions.plist скрипту `tooling/cross-platform/build-ios.sh`. Скрипт собирает узкий Go XCFramework из protocol/rivet/apple, затем Flutter IPA во временной копии без test-only plugin. В зависимости от вашей регистрации Apple экспортируйте development/ad-hoc/TestFlight. Сертификаты и закрытые ключи в архив не включаются.

RIVET использует штатный NEPacketTunnelProvider и packetFlow, без извлечения скрытого файлового дескриптора. Конфигурации хранятся в общей keychain group; SSH-секреты остаются в приватной группе приложения. Необходимы реальные проверки entitlements, memory budget NetworkExtension, сна, смены Wi-Fi/сотовой сети и восстановления после остановки. Проверка синтаксиса Swift и Go-пакетов на Ubuntu не является компиляцией Xcode.

## Сеть, хранение и завершение работы

Помощник слушает только loopback и требует случайный 256-битный токен. Перед передачей конфигурации клиент проверяет HMAC сервера; браузерные Origin-запросы отвергаются. Произвольные команды shell, пути файлов или PostUp/PostDown из импортируемых WG-конфигураций не исполняются.

На Ubuntu интерфейс xio019, собственная таблица 28691 и правила 18018/18019 принадлежат только помощнику. Не используйте эти идентификаторы для других VPN одновременно. Журнал root позволяет восстановить принадлежащие XIO правила после аварийного завершения. На Windows используются свой Wintun-адаптер и отдельное правило блокировки IPv6 с уникальным именем.

Текущие туннели передают IPv4; IPv6 блокируется при подключении, а не выпускается через обычную сеть. Полный системный kill switch между попытками соединения не реализован. При аварии и до восстановления сетевое поведение требует проверки на целевой ОС.

Закрытие интерфейса не посылает команду отключения отдельному помощнику: используйте кнопку отключения перед удалением приложения. Для восстановления после убитого помощника повторно запустите XIO и подключитесь/отключитесь; журнал удаляет только принадлежащие ему настройки. Не стирайте произвольные системные маршруты или firewall.

Удаление DEB: отключитесь и выполните `sudo apt remove xio-vpn`. Локальные профили остаются в пользовательском каталоге, как обычные настройки программы; удалить их можно отдельно после сохранения нужных экспортов. Удаление локального клиента само по себе не очищает VPS. Очистка VPS выполняется отдельным действием в настройках конкретного сервера.
