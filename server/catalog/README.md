# Каталог белых SNI (`server/catalog`)

Инструмент: [`tools/whitelist-catalog.py`](../../tools/whitelist-catalog.py).
Собирает каталог **точных FQDN**, пригодных как внешний SNI входа XIO (Xray REALITY
`serverName`/`dest`, RIVET/S1), из внешнего белого списка, и измеряет пригодность с того хоста,
где запущен.

## Что лежит здесь

| Файл | Назначение |
|---|---|
| `whitelist-pins.json` | **pin источника**: URL, ожидаемый `sha256`, коммит, лицензия. Обновляется только ревьюируемым коммитом |
| `whitelist-<YYYYMMDD>.json` | сгенерированный каталог (в git не коммитится) |
| `whitelist-manifest.json` | sha256 файла, `contentSha256`, sha256 предыдущей версии |
| `whitelist-previous.json` | N-1 для отката |

## Запуск

```bash
sudo python3 tools/whitelist-catalog.py \
  --commit "$(git rev-parse HEAD)" --interface eth0 --country FR
```

Проверки: источник скачивается только с хоста из pin, без редиректов, ≤ 5 МиБ; `sha256` источника
сверяется с pin; записи нормализуются в IDNA A-label; пробы идут с этого хоста и **мимо туннеля**
(`--interface`).

## Коды выхода

| Код | Значение |
|---|---|
| 0 | каталог собран |
| 2 | источник недоступен — каталог не меняется |
| 3 | `sha256` источника ≠ pin, или вход непригоден |
| 4 | пригодных меньше порога (`<10` или `<1 %`) либо превышен бюджет времени |
| 5 | ошибка записи/блокировки |

## Пригодность

Запись попадает в `eligible: true`, только если: имя из списка, резолвится, TCP 443 открыт,
сертификат валиден и покрывает имя, согласован **TLS 1.3** (обязателен для REALITY).
Причины отказа: `invalidEntry`, `unresolved`, `unreachable`, `certInvalid`, `certMismatch`, `tls12Only`.

Измерение на 03.11.2026 (список `hxehex/russia-mobile-internet-whitelist`, 910 записей, пробы с
Debian 13 в домашней сети): **439 пригодных**, `unresolved` 46, `unreachable` 204,
`tls12Only` 221. Пробы с самого сервера XIO могут дать другие числа — их и нужно публиковать в UI.

## Границы

- Помогает только при **SNI-only** фильтрации. При модели `ip+sni` (оператор сверяет и IP) эффекта нет.
- Не является маршрутизацией по доменам: клиентский split-routing принимает только IP/CIDR.
- Список — community-union без SLA; provenance обязателен, «список Минцифры» в UI не пишем.
