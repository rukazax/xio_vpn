# server/catalog — каталог «белых» SNI (P2, MVP A)

Строит `whitelist-<YYYYMMDD>.json` (schema 1) из запиненного публичного списка, проверяет
каждое имя с сервера XIO и пишет артефакт атомарно. Контракт: `work/ПРОЕКТ-2-БЕЛЫЙ-SNI-КОНТРАКТ.ru.md`.

Область — **SNI-only**. При модели `ip+sni` каталог эффекта не даёт: это фиксируется в отчёте,
а не замалчивается.

## Файлы

| Файл | Назначение |
|---|---|
| `catalog.py` | генератор: разбор, пробы, канонический хеш, атомарная запись, откат, подпись |
| `whitelist-pins.json` | pin источника (sha256 + коммит). Меняется только отдельным ревьюируемым коммитом |
| `lint_catalog.py` | проверка готового артефакта, тот же `lint_document`, что и в генераторе |
| `tests/test_catalog.py` | герметичные тесты, покрывают критерии приёмки 1–7 |
| `xio-catalog.service`, `xio-catalog.timer` | еженедельный запуск, `Persistent=true`, `RandomizedDelaySec=30m` |

Артефакты в git не кладутся: `whitelist-*.json`, `whitelist-previous.json`,
`whitelist-state.json`, `*.sig` — рабочее состояние сервера.

## Сборка

```sh
python3 catalog.py build --interface eth0 --country RU --node VPS-721137
```

Пробы идут **мимо туннеля**: сокет привязывается к физическому интерфейсу через
`SO_BINDTODEVICE`, поэтому важен `--interface`. Точка замера попадает в `probe.*`.

`--source-file` — офлайн-прогон по локальной копии источника (для отладки и тестов).

## Коды выхода

| Код | Значение |
|---|---|
| 0 | ок |
| 2 | источник недоступен |
| 3 | sha256 источника ≠ pin (или pin отсутствует), пустой/битый вход |
| 4 | пригодных меньше порога, превышен бюджет времени, вход больше лимитов |
| 5 | ошибка записи, отката, подписи; артефакт не проходит lint |

Артефакт не меняется ни при одном коде, кроме 0: всё считается в памяти, запись — последний шаг
(`tmp` → `fsync` → `rename`), предыдущий файл сохраняется вместе с sha256 в `whitelist-state.json`.

## Проверка и откат

```sh
python3 lint_catalog.py whitelist-20261103.json
python3 catalog.py rollback
```

Откат отказывается работать (код 5), если sha256 предыдущего артефакта не совпадает с манифестом.

## Тесты

```sh
python3 -m unittest discover -s server/catalog/tests -v
```

Тесты герметичны: сеть не используется, пробы подменяются. Тест `kill -9` посреди записи
выполняется только на Linux (нужны `SIGKILL` и `flock`).

## Подпись и доставка

`--sign-key` подписывает артефакт detach-подписью ed25519 (`<файл>.sig`), нужен пакет
`cryptography`. Приём подписи в приложении и отдача каталога через `client_api` — отдельный этап:
требуется закреплённый публичный ключ на клиенте.
