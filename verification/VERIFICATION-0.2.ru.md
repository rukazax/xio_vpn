## Что подтверждено сквозным сценарием

Лаборатории WireGuard и AmneziaWG используют независимые userspace endpoints с gVisor netstack. UDP слушает только 127.0.0.1:51829 и :51839; эмулятор обращается через 10.0.2.2. Нет host TUN, изменения маршрутов хоста, forwarding или root. Ключи случайные и временные.

Сценарий использует production MethodChannel, Android VpnService, Keystore и код хранилища:

1. Конфигурация с пересекающимися H1/H2 проходит Java-разбор, но отклоняется Go-движком. Ошибка не делает движок непригодным для следующего подключения.
2. Правильный AWG-профиль с Jc/Jmin/Jmax, S1–S4 и нестандартными H1–H4 устанавливает handshake, передаёт HTTP-запрос и получает ожидаемый ответ.
3. Проверяются ненулевые RX/TX и handshake, отсутствие открытого профиля/PrivateKey в файле vault и метаданных, отключение.
4. В том же процессе выполняется переход AWG → стандартный WireGuard → AWG с HTTP-ответами на каждом этапе и отключением между профилями.

После изменения интерфейса тест даёт Android одну секунду на обновление маршрутов. Успешный backend UP сам по себе остаётся показателем запуска интерфейса; интерфейс x1o отдельно показывает handshake. Один короткий HTTP-сеанс не является нагрузочным тестом.

Дополнительно точный подписанный release APK проверен через экран приложения: выбор AmneziaWG, импорт временного .conf, системное VPN-разрешение, подключение и 3/3 TCP-соединений к 10.77.0.1:8080 через AWG. Его SHA256 указан в `android-release-verification-0.2.json`. HTTP-payload в release отдельно не проверялся; он подтверждён автоматическим integration-сценарием.

## Исправления, связанные с проверкой

Первоначальная загрузка двух самостоятельных Go runtime (WireGuard AAR и AWG JNI) приводила к SIGSEGV при переключении. В итоговой версии **один** AmneziaWG backend; обычный WireGuard работает в совместимом режиме без AWG-параметров. Отдельная библиотека WireGuard AAR удалена из зависимостей 0.2.

Локальный UAPI-сокет AWG не создаётся: управление и статистика доступны только через JNI. Обращения к таблице native handles сериализованы mutex. Ошибка IpcSet закрывает созданный device, значение отклонённой конфигурации не выводится. Дублирующий upstream-поток опроса handshake отключён; используется сериализованный poller x1o.

Исходники и изменения перечислены в `../vendor/amneziawg/UPSTREAM.md`; Go-модуль закреплён `go.sum`. Go 1.27.2 собирается из отдельной копии runtime с CLOCK_BOOTTIME для таймеров сна. Оригинальная установка Go не меняется.

## Границы результата

- Положительная передача AWG и совместимость WireGuard проверены на Android x86_64 эмуляторе. ARM-библиотеки собраны, но не запускались на физических устройствах.
- Сквозной автоматический тест выполнялся в debug/test-варианте; release проверяется отдельно и его контрольная сумма фиксируется в BUILD-INFO.json.
- HeaderProtectionKey, I1–I5 и дополнительные параметры upstream принимаются импортом, но все их комбинации не проверялись. Пустые I1–I5 допустимы.
- В 0.2 мастер VPS по-прежнему устанавливает обычный WireGuard. AWG installer, RIVET, Xray/REALITY и остальные движки ещё не реализованы.
- Linux Tailscale-адаптер не менялся; прежний read-only status smoke относится к отчёту 0.1. Настоящий exit node, авторизация и Headscale не испытывались заново.
- Публичный интернет через VPS, DNS/IPv6 leaks, MTU, kill switch, переподключение после сна/смены сети, обход DPI в разных странах и устойчивость к взлому этим стендом не доказаны.
- Подпись — локальная development identity x1o, не публичная production-система обновления. Приватный ключ в поставку не включён.

Сборки 0.1 сохранены отдельно; прежние результаты не выдаются за проверку 0.2. Актуальные контрольные суммы установочных архивов и исходников — `../releases/SHA256SUMS`.
