# XIO 0.14.0+14 — удаление и автоматическая установка

Меню «Настройки → Серверы → ⋮» разделяет локальное удаление и очистку VPS. Локальное действие не подключается по SSH: удаляет сервер, пользователей, ключи обоих протоколов, SSH-пароль/делегированные ключи и обновляет план плитки. Удалённое действие доступно владельцу, автоматически использует сохранённый SSH-доступ, требует подтверждения в приложении и удаляет локальную запись только после успешного ответа VPS.

Перед удалением обновляется только собственный административный скрипт (около24KB) атомарной заменой. Работающий VPN-бинарный файл не перезаписывается. После очистки удалены /etc/xio-managed, /usr/local/lib/xio-managed, собственный бинарный файл /usr/local/bin/xio-amneziawg-go, конфигурация WireGuard, systemd units/timer, sysctl-файл, сокеты, lock-файл, делегированные ключи и собственные правила. Полный список пакетов, появившихся при установке0.14, включает bootstrap-зависимости. apt выполняет предварительный план удаления, RPM — проверку зависимостей без --nodeps. Чужие WireGuard-конфигурации и зависимости других программ защищены. Сохранённые общие пакеты перечисляются в результате.

«Все следы» означает собственные управляемые файлы/настройки XIO. Общесистемные журналы, история менеджеров пакетов, следы у провайдера и восстановление удалённых данных не входят в очистку. Для старой установки0.13 без полного package receipt безопасно удаляется только пакет с подтверждённым прежним владением.

## Системы

Автоматический bootstrap: Debian12/13; Ubuntu22.04/24.04/26.04; CentOS Stream, Rocky Linux, AlmaLinux, RHEL9/10. Требуются x86_64, systemd, TUN, исходящий IPv4, root SSH и доступ к настроенным официальным репозиториям. Python3/iproute устанавливаются при отсутствии; ARM64-серверы, CentOS7/8, Alpine/OpenRC и неизвестные системы отклоняются. Отказ по ОС/архитектуре происходит до создания каталогов установщика.

Пакетные команды сверены с [официальной инструкцией WireGuard](https://www.wireguard.com/install/). Работа firewalld использует раздельные runtime/permanent изменения и список собственных дополнений, без глобального reload/reset: [firewall-cmd](https://firewalld.org/documentation/man-pages/firewall-cmd.html). UFW остаётся включённым, удаляются только добавленные XIO-правила и профиль приложения. SELinux не отключается: бинарный файл размещается в стандартном /usr/local/bin с восстановлением штатного контекста.

Фактические испытания:

| Система | Проверка |
| --- | --- |
| Debian12, реальный VPS | Установка из Android; локальное удаление сохранило удалённый VPN; полная очистка из Android |
| Ubuntu24.04, отдельная KVM VM | UFW включён; WireGuard и AmneziaWG, свежие handshake и HTTPS HTTP200; очистка восстановила исходный набор пакетов и сохранила UFW/SSH |
| CentOS Stream9, отдельная KVM VM | firewalld включён, SELinux Enforcing; WireGuard и AmneziaWG, свежие handshake и HTTPS HTTP200; исходный набор пакетов восстановлен, firewall/SELinux сохранены |
| Остальные перечисленные версии | Реализована проверка версии и общий apt/RPM-путь; отдельное сетевое испытание каждой версии не выполнялось |

Образы Ubuntu/CentOS взяты с официальных cloud-images/cloud.centos.org; SHA256 проверены по опубликованным суммам. Испытания VM используют отдельное сетевое пространство имён и временный veth, не меняют маршруты хоста. Для подачи UDP из изолированного namespace временно разрешался вход только с тестового veth; публичные правила XIO не заменялись. Запрос HTTPS проходил через настоящий туннель, NAT и соответствующий firewall. Перед очисткой тестовая сеть удалялась. Это не испытание устойчивости к DPI, сетям разных стран или отсутствия всех утечек.

APK ARM64/ARMv7/x86_64 подписаны прежним сертификатом и проверены apksigner/zipalign16KB.

Доказательства: android-server-lifecycle-0.14.json, vps-app-cleanup-0.14.json, vm-ubuntu-lifecycle-0.14.json, vm-centos-lifecycle-0.14.json, android-apks-0.14.json. Сборка Ubuntu проверяет запуск интерфейса в Xvfb; Windows и физический Honor Magic V3 не проверены. Рабочие Android-протоколы в этом выпуске — WireGuard и AmneziaWG; остальные ранее запрошенные движки ещё не интегрированы.

После проверки итоговым APK сервер81.177.142.37 очищен от XIO: собственные каталоги, binary, units, sysctl, sockets/lock, WireGuard tools, интерфейсы, делегированные SSH-ключи и IPv4/IPv6-правила отсутствуют. SSH/nginx/apache2/exim4/dovecot активны. Локальная запись сервера и SSH-vault удалены автоматически. Прежние профили этой тестовой установки больше не действуют.

Полный цикл установки и локального удаления выполнен на кандидате0.14; после последних правок использован итоговый APK для подтверждённой очистки VPS и автоматического удаления локальной записи. Оба хеша сохранены в android-server-lifecycle-0.14.json. Серверная часть проверена в VM по точным SHA256 из отчётов.

Для повторения сетевого теста в одноразовой VM сохранён tools/lab-netns-probe.py; он ограничен hostname xio014-*, создаёт временные namespace/veth и два тестовых ключа. Использовать его на рабочем сервере не требуется.

APK ARM64 доставлен в Telegram; подтверждение и SHA256 — telegram-apk-delivery-0.14.json. Итоговые исходники и суммы — releases/XIO-0.14.0-source.zip и releases/SHA256SUMS.
