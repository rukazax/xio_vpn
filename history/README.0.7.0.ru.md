# x1o 0.5 — раздельное туннелирование Android

В **WireGuard и AmneziaWG** появились общие правила маршрутизации. Открыть: **Ещё → Раздельное туннелирование** либо строка текущего режима на главном экране. Сначала отключите VPN, выберите режим, сохраните правила и подключитесь заново. Подключение из плитки x1o использует те же правила.

- Все приложения: маршруты исходного профиля.
- Только выбранные приложения через VPN: остальные идут напрямую.
- Выбранные приложения в обход VPN: остальные используют маршруты профиля.
- Только выбранные IP/подсети через VPN: пересечение списка с AllowedIPs профиля.
- Выбранные IP/подсети в обход VPN: вычитание списка из AllowedIPs профиля.

Для приложений есть поиск по названию/пакету и счётчик выбора. Показываются приложения с ярлыком запуска и ранее сохранённые позиции. Android маршрутизирует по UID: приложения с общим UID могут разделять правило. Системная блокировка соединений без VPN может запретить обход. Скрытые сервисы без ярлыка отдельно не выбираются. Список не выгружается в облако.

IP-правила принимают буквальные IPv4, IPv6 и CIDR, до128 записей; адрес без маски означает один хост. Домены не поддерживаются. Режимы приложений и IP выбираются отдельно и не комбинируются. Правила никогда не расширяют AllowedIPs исходного профиля. Полностью пустое пересечение блокирует запуск. В IP-режимах незахваченные адреса обеих семей разрешены в обход VPN; при обычном режиме сохраняется исходное поведение защиты семей движка.

DNS остаётся из профиля. Для DNS через VPN его IP должен входить в маршруты; иначе разрешение имён может не работать. Автоматического добавления DNS-маршрутов и динамического определения IP сайтов нет. Это не заявление об отсутствии DNS/IPv6-утечек: выход напрямую в раздельных режимах является явно выбранным поведением.

Правила хранятся атомарно в Android no-backup storage, отдельно от зашифрованных ключей профиля; в экспорт метаданных/диагностики не входят. Пустой список «только выбранные приложения», недоступный выбранный пакет и повреждённые правила блокируют сохранение/запуск без молчаливого перехода на полный VPN. При удалении выбранного приложения снимите его отметку или выберите другой режим.

Подписанный APK для **Android ARM64**: [ARM64](releases/x1o-0.5.0-android-arm64-v8a.apk). Установка поверх0.4 с той же инженерной подписью; профили сохраняются. Автоматическая тема и компактная навигация сохранены. Ubuntu остаётся на проверенной сборке0.2; Windows — исходный проект. Раздельное туннелирование на ПК пока не реализовано.

Проверки: [отчёт0.5](verification/VERIFICATION-0.5.ru.md), [сценарии Android](verification/android-split-routing-0.5.json). Лаборатория и эмулятор не заменяют испытание на физическом телефоне и Debian VPS. Пароли VPS не сохраняются в исходниках и выпусках.

Основания поведения: [официальная документация Amnezia](https://docs.amnezia.org/ru/documentation/instructions/vpn-split-tunneling/), [Android VpnService.Builder](https://developer.android.com/reference/android/net/VpnService.Builder). Предыдущие описания ниже являются историей версий; текущие ограничения указаны выше.

# x1o 0.3 — плитка и уведомления Android

Android 0.3 добавляет плитку **x1o VPN** в быстрые настройки и foreground-уведомление VPN с кнопкой «Отключить». Предыдущие сборки сохранены в `releases/`.

Установите APK для архитектуры устройства (для большинства современных телефонов — arm64-v8a). В x1o откройте **Ещё → Android: шторка и уведомления → Добавить плитку x1o** и подтвердите системный запрос Android 13+. На Android 8–12 разверните шторку полностью, откройте редактирование плиток и перетащите x1o VPN. Приложение не может добавить плитку без участия пользователя.

Плитка показывает запуск VPN-интерфейса, а не доказательство интернет-доступа. В выключенном состоянии она открывает x1o и подключает выбранный профиль; если профиль отсутствует, приложение предложит добавить его. При первом подключении сохраняется системное VPN-разрешение. Нажатие активной плитки отключает VPN. На заблокированном экране сначала требуется разблокировка. Удержание плитки следует системному поведению Android.

При первом подключении на Android 13+ разрешите уведомления. Если отказали, откройте **Ещё → Настройки уведомлений**. При запрете уведомлений Android VPN может работать, но состояние может не отображаться в обычной шторке. Foreground-уведомление принадлежит реальной VPN-службе и сохраняется при переходе на домашний экран. Оно открывает приложение и позволяет отключить VPN. Уведомление скрывается после остановки службы, ошибки активации и отзыва системного VPN-доступа. Принудительная остановка приложения отключает службу; автоматического восстановления после перезагрузки и kill switch по-прежнему нет.

Системные настройки позволяют скрыть/отключить уведомления или изменить порядок плиток. Поведение конкретных OEM-оболочек требует проверки на телефоне. Отчёт: [verification/VERIFICATION-0.3.ru.md](verification/VERIFICATION-0.3.ru.md).

Версия 0.3 поставляется как обновление Android; Ubuntu остаётся на проверенной сборке 0.2, Windows — исходный проект. Функции и ограничения базового VPN описаны ниже.

# x1o — X in, 1 out

Инженерная версия **0.2.0**, 17 октября 2026 года. Собственная оболочка Flutter для Android, Ubuntu и Windows. Она начинает реализацию согласованного продукта; это **ещё не полный аналог Amnezia и не завершённая реализация RIVET**.

## Что реализовано

- Адаптивный интерфейс на русском: подключение, профили, протоколы, лаборатория, настройки и журнал сеанса.
- Бренд: сходящиеся пути и единый выход; собственные SVG/PNG/launcher icons, Noto Sans с кириллицей, локальные шрифты.
- Android: нативный AmneziaWG Go `v3.1.20260814` с режимами AWG и обычного WireGuard, системное разрешение VPN, импорт однопирингового `.conf`, подключение/отключение, счётчики и время handshake.
- Android: AES-GCM для конфигураций с ключом Android Keystore; секреты находятся в `noBackupFilesDir`, backup приложения выключен. Степень аппаратной защиты Keystore зависит от устройства и здесь не гарантируется.
- Desktop: адаптер к установленному Tailscale через CLI, чтение реального состояния, запрос up/down и выбор доступного exit node. Headscale используется через уже настроенную штатную службу.
- SSH-мастер на всех трёх целевых платформах: пароль/PEM, обязательное сравнение доверенного SHA256-отпечатка, предпроверка VPS и просмотр сценария перед запуском.
- Экспериментальный рецепт установки WireGuard на Ubuntu 24.04: один клиент, IPv4-выход, собственный интерфейс `x1o0`, локальная генерация клиентского ключа. Сценарий выполняется только по кнопке применения плана на выбранном VPS.
- Диагностика DNS и трёх TCP-соединений к указанному пользователем адресу; JSON-отчёт без профилей и ключей.

Наличие кода интеграции не приравнивается к проверке всех платформ. Подробные доказательства и границы — в [отчёте проверки](verification/VERIFICATION-0.2.ru.md).

## Быстрый запуск

### Android

Установите APK из `releases/`. Откройте «Серверы → Добавить профиль», вставьте стандартный WireGuard `.conf`, сохраните и нажмите «Подключиться». Системный Android-диалог VPN должен быть разрешён пользователем. После запуска проверьте handshake и трафик: один активный интерфейс не доказывает доступность сервера.

В этой версии принимаются один `[Interface]` и один `[Peer]`. Shell hooks отклоняются; поля AmneziaWG принимаются только при выборе движка AmneziaWG. `AllowedIPs` определяет область туннелирования: профиль с одним частным CIDR не защищает весь интернет. Для захвата всего IPv4/IPv6 нужны соответствующие маршруты и работоспособный выход; IPv6 обязательно проверяется отдельно.

Kill switch, always-on и split tunneling **пока не реализованы**. Отключение/сбой VPN может вернуть обычный сетевой маршрут. `SUPPORTS_ALWAYS_ON=false` запрещает выдавать неподдерживаемый режим за работающий.

### Ubuntu

Распакуйте архив Linux целиком, перейдите в каталог `bundle/` и запустите `./x1o`. Файлы `lib/` и `data/` должны оставаться рядом с бинарником. Требуются desktop runtime GTK3 и совместимая Ubuntu x64. Для Tailscale установите и авторизуйте штатный клиент, затем добавьте профиль Tailscale в x1o.

Адаптер не устанавливает службу и не повышает права автоматически. Если служба требует root/operator-разрешения, настройте допустимого оператора штатным способом отдельно. Выбор exit node меняет маршрутизацию всей системной службы, включая другие приложения; доступ к LAN при выборе через x1o выключается.

WireGuard desktop в 0.2 не интегрирован. Конфигурацию, созданную мастером VPS, можно сохранить в отдельном клиенте WireGuard. Tailscale не становится незаметным для DPI из-за наличия DERP.

### Windows

Предоставлен исходный Flutter-проект Windows и сценарий `tools/build-windows.ps1`. Нужны Flutter SDK и Visual Studio с Desktop development with C++. **Windows EXE на Ubuntu не собран и на Windows не проверен.** Tailscale ожидается в `%ProgramFiles%\Tailscale\tailscale.exe`.

## VPS

В мастере указываются адрес, SSH-порт, пользователь и доверенный SHA256-отпечаток. Отпечаток берётся из независимой консоли провайдера, например для выбранного ключа `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`. Несовпадение прерывает соединение.

Предпроверка читает ОС, архитектуру, UID, маршруты и слушающие порты. Рецепт установки требует Ubuntu 24.04 и root через SSH; sudo-поток не реализован. Существующий `x1o0`, конфликт подсети/порта и активный UFW приводят к отказу установки. Другие firewall-схемы требуют отдельного анализа.

План явно включает пакеты WireGuard/iptables, IPv4 forwarding, интерфейс `10.77.0.0/24`, UDP51820, правила NAT/forward, systemd и блокирование пересылаемого клиентского IPv6. Это **не IPv6 exit node**. Для UDP51820 может понадобиться разрешение в firewall провайдера. DNS клиента в этом рецепте — `1.1.1.1`; запросы идут через туннель при исправном IPv4-выходе.

Пакеты берутся из настроенных репозиториев VPS, фактические версии пишутся в `/var/log/x1o-install.log`. Это лабораторный рецепт, а не универсальный транзакционный установщик: после сбоя могут остаться пакеты и конфигурация. Предусмотрена попытка остановить собственную службу и восстановить прежний IPv4 forwarding; полного отката всех частично добавленных firewall-правил не гарантируется. Не удаляйте чужие правила ради повторного запуска.

Успешный запуск systemd ещё не подтверждает интернет через VPS. Требуются handshake, внешний IPv4, DNS, поведение IPv6, MTU и проверки при сбое выхода. Без доступного тестового VPS эти проверки не выполнены.

```text
  └─ AppStore: профили, состояние, сериализованная атомарная запись метаданных
      ├─ Android MethodChannel → единственный GoBackend AmneziaWG (AWG / WireGuard) → VpnService
      │                          └─ Android Keystore / AES-GCM vault
      ├─ Ubuntu/Windows → Process без shell → системный tailscale CLI
      ├─ VpsService → SSH с pinning → preflight → просмотр плана → установка
      └─ NetworkChecks → DNS / TCP → отчёт без секретов
```

`lib/core.dart` содержит модели, валидацию, хранилище и адаптеры; `lib/main.dart` — UI. Android-код — `android/app/src/main/kotlin/app/x1o/x1o/MainActivity.kt`. Рецепт — `assets/install-wireguard.sh`. Независимый лабораторный WireGuard endpoint — `lab/`; он не изменяет сетевые маршруты хоста и слушает UDP только на loopback.

Секреты SSH не сохраняются приложением на диск и не включаются в журнал. Это не обещание гарантированного обнуления памяти Dart/Android. Копирование конфигурации в буфер — отдельное явное действие пользователя; после него ключ доступен через системный clipboard согласно правилам ОС.

## Сборка и воспроизводимость

Для Flutter3.47.7 в Android Gradle добавлен точечный release-only обход регистрации dev-плагина `integration_test`: тестовый плагин не входит в APK. Подробности — в отчёте проверки.

SDK исходной сборки: Flutter 3.47.7 / Dart 3.13.5. Android: API36, minSdk26, NDK30.0.16248370, AmneziaWG Go v3.1.20260814. Dart-пакеты закреплены в `pubspec.lock`.

```bash
cd app
flutter pub get
flutter analyze
flutter test
flutter build apk --release
flutter build linux --release
```

Для Linux-сборки нужны CMake, Ninja, Clang и GTK3 development headers. На текущем хосте они распакованы локально в `.build-support/gtk-root/`; `tools/build-linux.sh` использует их при наличии, системные библиотеки не заменены.

Android release подписывается отдельным локальным ключом разработки x1o из `.signing/`. Ключ и пароли **не входят в исходный ZIP**. Сохраните эту папку отдельно в защищённом месте для выпуска обновлений с той же подписью. На новой машине перед APK-сборкой запустите `python3 tools/create-signing-key.py`: это создаёт другую идентичность подписи; такой APK не является обновлением уже установленного приложения без переустановки. Debug и release-подписи также различаются.
