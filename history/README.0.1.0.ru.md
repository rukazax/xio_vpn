# x1o — X in, 1 out

Инженерная версия **0.1.0**, 16 октября 2026 года. Собственная оболочка Flutter для Android, Ubuntu и Windows. Она начинает реализацию согласованного продукта; это **ещё не полный аналог Amnezia и не завершённая реализация RIVET**.

## Что реализовано

- Адаптивный интерфейс на русском: подключение, профили, протоколы, лаборатория, настройки и журнал сеанса.
- Бренд: сходящиеся пути и единый выход; собственные SVG/PNG/launcher icons, Noto Sans с кириллицей, локальные шрифты.
- Android: нативный WireGuard `com.wireguard.android:tunnel:1.0.20260102`, системное разрешение VPN, импорт стандартного однопирингового `.conf`, подключение/отключение, счётчики и время handshake.
- Android: AES-GCM для конфигураций с ключом Android Keystore; секреты находятся в `noBackupFilesDir`, backup приложения выключен. Степень аппаратной защиты Keystore зависит от устройства и здесь не гарантируется.
- Desktop: адаптер к установленному Tailscale через CLI, чтение реального состояния, запрос up/down и выбор доступного exit node. Headscale используется через уже настроенную штатную службу.
- SSH-мастер на всех трёх целевых платформах: пароль/PEM, обязательное сравнение доверенного SHA256-отпечатка, предпроверка VPS и просмотр сценария перед запуском.
- Экспериментальный рецепт установки WireGuard на Ubuntu 24.04: один клиент, IPv4-выход, собственный интерфейс `x1o0`, локальная генерация клиентского ключа. Сценарий выполняется только по кнопке применения плана на выбранном VPS.
- Диагностика DNS и трёх TCP-соединений к указанному пользователем адресу; JSON-отчёт без профилей и ключей.

Наличие кода интеграции не приравнивается к проверке всех платформ. Подробные доказательства и границы — в [отчёте проверки](verification/VERIFICATION.ru.md).

## Быстрый запуск

### Android

Установите APK из `releases/`. Откройте «Серверы → Добавить профиль», вставьте стандартный WireGuard `.conf`, сохраните и нажмите «Подключиться». Системный Android-диалог VPN должен быть разрешён пользователем. После запуска проверьте handshake и трафик: один активный интерфейс не доказывает доступность сервера.

В этой версии принимаются один `[Interface]` и один `[Peer]`. Shell hooks и поля AmneziaWG отклоняются. `AllowedIPs` определяет область туннелирования: профиль с одним частным CIDR не защищает весь интернет. Для захвата всего IPv4/IPv6 нужны соответствующие маршруты и работоспособный выход; IPv6 обязательно проверяется отдельно.

Kill switch, always-on и split tunneling **пока не реализованы**. Отключение/сбой VPN может вернуть обычный сетевой маршрут. `SUPPORTS_ALWAYS_ON=false` запрещает выдавать неподдерживаемый режим за работающий.

### Ubuntu

Распакуйте архив Linux целиком и запустите `./x1o`. Файлы `lib/` и `data/` должны оставаться рядом с бинарником. Требуются desktop runtime GTK3 и совместимая Ubuntu x64. Для Tailscale установите и авторизуйте штатный клиент, затем добавьте профиль Tailscale в x1o.

Адаптер не устанавливает службу и не повышает права автоматически. Если служба требует root/operator-разрешения, настройте допустимого оператора штатным способом отдельно. Выбор exit node меняет маршрутизацию всей системной службы, включая другие приложения; доступ к LAN при выборе через x1o выключается.

WireGuard desktop в 0.1 не интегрирован. Конфигурацию, созданную мастером VPS, можно сохранить в отдельном клиенте WireGuard. Tailscale не становится незаметным для DPI из-за наличия DERP.

### Windows

Предоставлен исходный Flutter-проект Windows и сценарий `tools/build-windows.ps1`. Нужны Flutter SDK и Visual Studio с Desktop development with C++. **Windows EXE на Ubuntu не собран и на Windows не проверен.** Tailscale ожидается в `%ProgramFiles%\Tailscale\tailscale.exe`.

## VPS

В мастере указываются адрес, SSH-порт, пользователь и доверенный SHA256-отпечаток. Отпечаток берётся из независимой консоли провайдера, например для выбранного ключа `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`. Несовпадение прерывает соединение.

Предпроверка читает ОС, архитектуру, UID, маршруты и слушающие порты. Рецепт установки требует Ubuntu 24.04 и root через SSH; sudo-поток не реализован. Существующий `x1o0`, конфликт подсети/порта и активный UFW приводят к отказу установки. Другие firewall-схемы требуют отдельного анализа.

План явно включает пакеты WireGuard/iptables, IPv4 forwarding, интерфейс `10.77.0.0/24`, UDP51820, правила NAT/forward, systemd и блокирование пересылаемого клиентского IPv6. Это **не IPv6 exit node**. Для UDP51820 может понадобиться разрешение в firewall провайдера. DNS клиента в этом рецепте — `1.1.1.1`; запросы идут через туннель при исправном IPv4-выходе.

Пакеты берутся из настроенных репозиториев VPS, фактические версии пишутся в `/var/log/x1o-install.log`. Это лабораторный рецепт, а не универсальный транзакционный установщик: после сбоя могут остаться пакеты и конфигурация. Предусмотрена попытка остановить собственную службу и восстановить прежний IPv4 forwarding; полного отката всех частично добавленных firewall-правил не гарантируется. Не удаляйте чужие правила ради повторного запуска.

Успешный запуск systemd ещё не подтверждает интернет через VPS. Требуются handshake, внешний IPv4, DNS, поведение IPv6, MTU и проверки при сбое выхода. Без доступного тестового VPS эти проверки не выполнены.

## Архитектура

```text
Flutter UI
  └─ AppStore: профили, состояние, сериализованная атомарная запись метаданных
      ├─ Android MethodChannel → единственный GoBackend WireGuard → VpnService
      │                          └─ Android Keystore / AES-GCM vault
      ├─ Ubuntu/Windows → Process без shell → системный tailscale CLI
      ├─ VpsService → SSH с pinning → preflight → просмотр плана → установка
      └─ NetworkChecks → DNS / TCP → отчёт без секретов
```

`lib/core.dart` содержит модели, валидацию, хранилище и адаптеры; `lib/main.dart` — UI. Android-код — `android/app/src/main/kotlin/app/x1o/x1o/MainActivity.kt`. Рецепт — `assets/install-wireguard.sh`. Независимый лабораторный WireGuard endpoint — `lab/`; он не изменяет сетевые маршруты хоста и слушает UDP только на loopback.

Секреты SSH не сохраняются приложением на диск и не включаются в журнал. Это не обещание гарантированного обнуления памяти Dart/Android. Копирование конфигурации в буфер — отдельное явное действие пользователя; после него ключ доступен через системный clipboard согласно правилам ОС.

## Дальнейшая реализация

| Направление | Состояние 0.1 |
|---|---|
| Android WireGuard | Нативный движок включён; см. доказательства проверки |
| Ubuntu Tailscale | Адаптер включён; status проверяется на реальной службе |
| Windows Tailscale | Код предусмотрен; сборка и испытание Windows впереди |
| Android Tailscale / Headscale | Встраивание backend ещё не выполнено |
| AmneziaWG 3.1, Xray/VLESS/REALITY/Vision, OpenVPN, IKEv2, Shadowsocks | Требования сохранены; движки ещё не входят в дистрибутив |
| RIVET H3/S1 | Предварительная спецификация; движок отсутствует |
| Headscale/DERP installer | Спроектирован в исследовании; установочный рецепт ещё не реализован |
| Отзыв устройств, серверные политики, QR, обновления, kill switch | Ещё не реализованы |
| VPS/физический телефон/Windows | Требуют отдельных стендовых проверок |

Каталог показывает отсутствующие движки как «В разработке» и не позволяет подменить их фиктивным подключением. Удаление локального профиля **не отзывает** его публичный ключ на сервере.

## Сборка и воспроизводимость

Для Flutter3.47.7 в Android Gradle добавлен точечный release-only обход регистрации dev-плагина `integration_test`: тестовый плагин не входит в APK. Подробности — в отчёте проверки.

SDK исходной сборки: Flutter 3.47.7 / Dart 3.13.5. Android: API36, minSdk26, NDK30.0.16248370, WireGuard tunnel1.0.20260102. Dart-пакеты закреплены в `pubspec.lock`.

```bash
cd app
flutter pub get
flutter analyze
flutter test
flutter build apk --release
flutter build linux --release
```

Для Linux-сборки нужны CMake, Ninja, Clang и GTK3 development headers. На текущем хосте они распакованы локально в `.build-support/gtk-root/`; `tools/build-linux.sh` использует их при наличии, системные библиотеки не заменены.

Android release подписывается отдельным локальным ключом разработки x1o из `.signing/`. Ключ и пароли **не входят в исходный ZIP**. Сохраните эту папку отдельно в защищённом месте для выпуска обновлений с той же подписью. На новой машине перед APK-сборкой запустите `python3 tools/create-signing-key.py`: это создаёт другую идентичность подписи; такой APK не является обновлением уже установленного приложения без переустановки. Debug и release-подписи также различаются.
