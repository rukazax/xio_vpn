XIO Client privacy policy — Windows, Ubuntu and iOS source candidates
Revision: 24 October2026. Developer: Konstantin Eryomin, er-ka@mail.ru.
Profiles, settings and acknowledgement records stay on this device. VPN profiles and restricted account tokens are sensitive. iOS uses Keychain; Windows uses user DPAPI; Ubuntu uses AES-GCM with a local device key protected by directory/file permissions. This is not protection against a compromised account or operating system. Client desktop storage is separate from the full application's storage.
The client connects to an existing server and does not deploy/administer servers or accept server SSH/root/admin credentials. An explicitly issued restricted HTTPS token may create/revoke only the account's subclients under the server quota; child exports do not inherit the parent token. The server also stores subclient records.
Traffic between device and selected server is encrypted by the selected transport. The server operator can observe connecting IP addresses, destinations and metadata. Destination HTTPS separately protects content. The selected HTTPS connectivity-check website sees the exit address. There is no advertising/analytics SDK or automatic crash reporting. Optional support messages are voluntary; never send private keys or passwords.
Native protocol availability differs: iOS currently declares RIVET/H3 and S1; Windows/Ubuntu also declare AWG and Xray. Cloak on desktops and AWG/Xray/Cloak on iOS are not implemented. Source preparation and profile-codec tests are not native acceptance. Network permissions and supported routes depend on the OS/backend. No universal kill-switch, split-routing, screenshot protection or background persistence is claimed for these candidates.
Deleting a local profile does not revoke its server access. Local data remains until removed or the application's private data is deleted; server processing is controlled by its operator. Acknowledgement stores revision, device UTC clock, language and displayed-text SHA256 locally and is not sent to the developer.
