# XIO Client 0.22.2

Отдельный облегчённый Android-клиент на основе текущего XIO 0.22.2+5006. Идентификатор пакета `app.x1o.client`: устанавливается рядом с полной версией, её данные не меняет. Интерфейс клиента — русский; документы доступны на русском и английском. Это локально подготовленная сборка, без заявления о проверке на физическом телефоне.

## Что умеет

- Импортировать готовые клиентские ключи XIO/Amnezia и конфигурации, которые принимает текущий валидатор XIO.
- Подключать выбранный профиль AmneziaWG, Xray, RIVET/S1, RIVET/H3 или OpenVPN/Cloak. Самостоятельные WireGuard/OpenVPN/IKEv2/Shadowsocks/Tailscale не возвращены.
- Хранить несколько профилей и переключаться между серверами: подтверждение → отключение → проверка остановки → выбор → новое подключение. При неудачной остановке переключение отменяется. Клиент не подменяет выбранный профиль другим протоколом.
- Использовать системный VPN и фоновую службу с уведомлением и отключением, существующие механизмы восстановления туннеля и быстрой плитки.
- Раздельное туннелирование: все приложения; только выбранные через VPN; выбранные в обход; отдельно включение/исключение IP/CIDR IPv4/IPv6. Правила локальные, общие для профилей. Пустой список включения, повреждённые правила и отсутствующие выбранные приложения отклоняются. Правила меняются при отключённом VPN.

Установки VPS, SSH, администрирования сервера, раздачи VPN, геолокации серверов, аналитики запуска, установщика обновлений и серверных архивов в клиенте нет. Административные ключи и bundles с SSH-доступом отклоняются. Секреты профилей хранятся прежним Android Keystore/AES-GCM механизмом; резервное копирование отключено. `FLAG_SECURE` запрещает снимки и содержимое приложения в обзоре последних задач.

## Установка и подключение

Требуется Android 8.0 / API 26 или новее. Подготовлены ARM32 (`armeabi-v7a`), ARM64 (`arm64-v8a`), x86-64 и универсальный APK с тремя архитектурами. На Android ниже 8.0 и 32-битном x86 эта база не поддерживается; совместимость с каждым устройством или прошивкой не заявляется.

1. Установите соответствующий APK из `releases/client-0.22.2`. Универсальный выбирает подходящую архитектуру, отдельный APK занимает меньше места при скачивании.
2. Ознакомьтесь с двумя уведомлениями. Получите **клиентский** профиль существующего сервера у его администратора; встроенной базы адресов и встроенных чужих секретов нет.
3. Нажмите «Добавить профиль», вставьте ключ или выберите файл. Выберите сервер и нажмите «Подключить»; Android отдельно запросит разрешение VPN.
4. Для разделения трафика сначала отключитесь, откройте правила и сохраните нужный режим. Исключённый трафик идёт напрямую, если Android lockdown не блокирует его.

Правила приложений и IP — отдельные режимы; доменных правил нет. Список приложений ограничен запускаемыми приложениями, видимыми Android; общий UID и рабочие профили требуют отдельной проверки. VPN проверяет доступность выбранного HTTPS-сайта. При исключении самого XIO Client такая проверка может идти напрямую и не доказывает защиту других приложений. При ручном переключении есть промежуток без VPN: для блокировки используйте системные Always-on VPN и «Блокировать соединения без VPN». Принудительная остановка приложения может прервать туннель. RIVET — экспериментальные транспорты; гарантий анонимности, обхода любой блокировки или независимого криптоаудита нет.

## Сборка и проверка

Из корня соответствующего полного дерева исходников с закреплёнными native/vendor компонентами:

```sh
python3 client/build.py
```

Скрипт создаёт изолированное дерево `.build-support/client`, исключает серверные assets и 16-МБ CJK-шрифт, сохраняет системные шрифты, меняет manifest только в staging, использует `lib/client_main.dart` и `XIO_CLIENT_ONLY=true`. Нативный слой отдельно запрещает SSH-хранилище, раздачу VPN и updater через `BuildConfig.CLIENT_ONLY`. Нужны установленные SDK/Flutter и настроенная локальная подпись `.signing/signing.properties`; секреты подписи в исходники и отчёт не входят. Подмена native runtime произвольным upstream недопустима. См. также `docs/ru/build.md` и `native-sources/android-runtime-0.22`.

После сборки скрипт копирует четыре APK и хеши исходных входов в `releases/client-0.22.2`, затем запускает `client/verify.py`: проверяются package ID, launcher aliases, отсутствие updater-компонентов/установочного разрешения и серверных assets, отсутствие SSH/геолокационных строк в Dart AOT, подпись, выравнивание ZIP/ELF и соответствие загруженных native-секций текущим исходным бинарникам. Результаты — `verification.json`, `SHA256SUMS`, `source-inputs.json`.

Предыдущая проверка базового клиента 0.22.1:

- `flutter analyze` по затронутым Dart-файлам и новому тесту — без замечаний.
- Пять новых client-only тестов: отказ от admin-доступа до native IO, точный выбор профиля, порядок переключения, отказ при неостановленном туннеле, экран 320 px с масштабом текста 1.5.
- Общий прогон пяти связанных наборов — 32 пройденных теста; client-only прогон клиента/согласий/маршрутизации — 15 пройденных тестов, с пересечением наборов.
- Production-класс `IpRoutes` с Java-проверками IPv4/IPv6, ошибочных литералов, пересечения маршрутов и 20 480 выборок дополнения.

Эти проверки не подтверждают работу VPN, split tunnelling, Always-on или обновлений на физическом Android и конкретном сервере: телефон и реальные серверы в этой задаче не использовались. Сетевое поведение движков сохранено из текущей версии; проверено совпадение native payload в APK.

## Изменения 0.22.2: экран и субклиенты

Главный экран использует общую с полной версией тему `app_theme.dart`: круглая кнопка 230×230, состояние, компактное раздельное туннелирование, карточка выбранного сервера и RX/TX. Список серверов открывается из карточки. Возвращён основной Noto Sans (около 0,5 МБ); большой CJK-шрифт не включён.

Для обычного VPN-профиля создание субклиентов недоступно. Для аккаунта с выданным API-доступом доступна кнопка «Субклиенты»: сервер сообщает лимит, занятое и свободное число; можно создать клиента, передать только его VPN-профили или отозвать своего клиента. Квота применяется сервером под общей блокировкой, включая параллельные устройства. Никакое поле из импортированного профиля не увеличивает серверный лимит. Субклиент не получает API-токен родителя и не может создавать следующих клиентов.

Для существующего сервера нужна серверная версия recipe 21 и новый клиентский профиль schema 3. Порядок для владельца:

1. Использовать обновлённую **полную** Android-версию 0.22.2 и отключить VPN перед выдачей доступа.
2. У нужной учётной записи должны быть действующие права создания пользователей и положительный `userLimit` (1–250). В полной версии открыть «Пользователи» → «Поделиться» для этой учётной записи.
3. Подтверждение явно описывает включение отдельного HTTPS API на TCP 9444 и отзыв старого API-токена этой учётной записи. Только владелец с проверенной SSH-идентичностью может обновить сервер и выдать такой профиль. Старые делегированные SSH-ключи этим действием в клиент не передаются.
4. Импортировать полученный профиль в XIO Client, проверить показанный адрес API и подтвердить добавление аккаунта. Повторный импорт обновляет API-доступ существующего пользователя, не заменяет VPN-профили и не теряет незавершённую операцию.

Серверный компонент включается только после этого действия владельца: в этой задаче ни один VPS не изменялся. Требуются systemd, OpenSSL, useradd/nologin и существующие iptables/ip6tables; внешний firewall провайдера также должен разрешать TCP 9444. Внешний HTTPS frontend работает от отдельного системного пользователя без shell и прав root. Отдельный root-dispatcher доступен только через локальный UNIX-сокет и независимо проверяет токен, точный список действий (`status/add/revoke`), отзыв, принадлежность и квоту. Готовность службы при выдаче проверяется systemd. Проверка установки служб и работа на конкретном VPS в этой задаче не выполнены.

Токен случайный 256-битный, на сервере хранится его SHA-256, в Android — отдельная запись Keystore/AES-GCM без резервного копирования. Сервер выдаёт клиенту только endpoint, публичный SHA-256 сертификата, токен, userId/serverId. В клиентских экспортируемых пакетах отсутствуют adminAccess, пароль, SSH-ключ, root-ключ, сертификатный private key сервера и права на дальнейшее делегирование. Нативные readConfig/deleteConfig клиента ограничены ID VPN-профилей: чтение SSH-хранилища через эти методы тоже закрыто. Общий доступ использует только временный файл профиля через cache-only FileProvider.

Клиент закрепляет точный DER-сертификат, endpoint и срок его действия, не следует redirect и не пересылает токен другому адресу. Сертификат этого API отдельный, самоподписанный, срок — 365 дней; его продление/замена требует действий владельца и новых клиентских профилей с новым pin. Это не отключение TLS-проверки для всех сертификатов. См. [Dart SecurityContext](https://api.dart.dev/dart-io/SecurityContext/SecurityContext.html) и [HttpClient certificate callback](https://api.flutter.dev/flutter/dart-io/HttpClient/badCertificateCallback.html).

Перед созданием клиент сохраняет ID операции и свои новые VPN-ключи в защищённом хранилище. После обрыва «Проверить незавершённое создание» использует тот же ID/параметры; сервер возвращает сохранённый результат, не создаёт ещё одного пользователя. При серверном `pending` после аварии требуется отдельная сверка владельцем; автоматического повторного исполнения нет. После отзыва дочернего доступа сохранённые сервером клиентские профили из его операции удаляются.

Проверки нового поведения: 26 серверных unit-тестов (включая 6 новых проверок API), тесты подменённого сертификата/redirect, схемы 3 и отказа от root/admin полей, отсутствия родительского токена в дочернем профиле, сохранения ID/ключей после timeout; общие Flutter-регрессии и проверки APK. Это локальные проверки, не независимый аудит и не испытания физического Android/VPS. HTTPS frontend основан на ограниченном обработчике Python `http.server`; [Python не рекомендует этот модуль для production](https://docs.python.org/3/library/http.server.html). Серверная часть остаётся предварительной: до массового развёртывания необходимы отдельная проверка установки/нагрузки и production transport review. Пользовательский экран и права нельзя считать подтверждением безопасности всей инфраструктуры.

Итоговая проверка 0.22.2: `flutter analyze` без замечаний; 110 общих Flutter-тестов прошли, 5 пропущены; отдельно 10 тестов в клиентском режиме и 26 серверных тестов прошли. Проверен формат запросов JSON UTF-8 с точным Content-Length и передача через локальный UNIX-сокет. Тестовые изображения экрана используют вымышленные профили.
