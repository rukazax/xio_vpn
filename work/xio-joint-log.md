## 2026-11-03, поздний вечер — W11 и rc4

**W11 (изоляция клиентов) реализована** (`f0db6a6`) по схеме xio: правила вставляются через `-I`,
поэтому список в коде идёт в обратном порядке и в цепочке получается «ACCEPT в аплинк → ACCEPT
RELATED → ACCEPT RELATED/ESTABLISHED на возврате → DROP остального». `RELATED` добавлен отдельно:
при MTU 1232 ICMP «fragmentation needed» классифицируется как RELATED, без него крупные пакеты
молча умирают. Широкое правило 0.24.0 (`-i xioawg0 -j ACCEPT`) удаляется при применении.

Проверено на живой паре: телефон сохраняет IPv4 (21 мс) и IPv6 через каскад (3/3), клиент из
лаборатории больше **не может** достучаться до туннельного адреса телефона (100 % потерь).
Правила применяются при старте AWG (`start_awg` → `rules`), поэтому на сервере выполнён
`systemctl restart xio-managed-awg`; состояние до правки сохранено в `/root/fwd-before-*.txt`.

**AWG 3.0/3.1:** профиль теперь зеркалит **все** параметры развёртывания (`S3`, `S4`, `I1..I5`,
если они заданы), а не только `Jc/Jmin/Jmax/S1/S2/H1..H4`. Для текущего развёртывания профиль
не изменился — отсутствующие параметры на обеих сторонах равны нулю, поэтому телефон с AmneziaWG 3.1
и Linux-клиент работают; если включить S3/S4 на сервере, клиент получит их автоматически.

## 2026-11-04 — MTU-развязка и rc6

xio принял rc5 и уточнил механизм: `ip link set … mtu 1232` при наличии IPv6 **не падает** (rc=0),
а молча снимает все IPv6-адреса с интерфейса; падает следующий шаг (`dualstack().apply()`), откуда
и бралось `IPv6 network operation failed`. Поэтому 1232 на устройстве невозможен (и по RFC 8200
минимум канала — 1280), а 1232 остаётся PMTU пути; крупные пакеты проходят за счёт ICMP
frag-needed, который правила изоляции разрешают через `RELATED`.

В `66982bf` добавлен страж: после смены MTU проверяется, что `fd78:1::1` на месте, иначе
`RuntimeError` — чтобы будущая правка MTU падала громко, а не оставляла интерфейс без IPv6.
Там же убран дублирующий `unittest.main()` перед `IsolationRulesTests` (при прямом запуске
`test_admin.py` два новых теста не существовали); прямой прогон теперь даёт 24 теста.

**rc6** (`66982bf`): архив `d2cdb986…` (33 члена), Windows `82533bc5…`, Ubuntu deb `6d87caed…`,

## 2026-11-04, день — fd-баг, xray protobuf, hardening exit

Главное: утренний флейк cloak-теста оказался не регрессией переписывания Xray-конфига, а реальным
багом с дескрипторами, который был в коде и раньше. После исправления переписывание принято.
Код с этими правками уже в дереве (коммит `c2b3338`), ниже — только документы; git-операций в этом
проходе не выполнялось. Факты из отчётов

**fd-баг (`protocol/rivet/mobile/awg_unix.go`).** `tun.CreateUnmonitoredTUNFromFD` сначала делает
`os.NewFile(fd)` (объект с финализатором) и только потом валидирует `TUNGETIFF`; на неподходящем
дескрипторе возвращает ошибку, **не закрывая** созданный `*os.File`. Дальше `AwgTurnOn` закрывал
тот же номер вторым `unix.Close` — номер освобождался и уходил следующему сокету, а финализатор
брошенного `*os.File` позже закрывал уже чужой сокет. Проявлялось только в паре тестов и зависело
от `GOGC` (`off`/`1000`/`10` — 0 падений, дефолт `100` — 8/20), то есть это был отложенный `close(2)`:
у cloak это `accept tcp …: i/o timeout`, `accept4: bad file descriptor` и `accept4: invalid argument`.
Исправление: конструктору отдаётся дубликат через `F_DUPFD_CLOEXEC`, исходный дескриптор закрывает
сам `AwgTurnOn`; успешный путь проверен на реальном `/dev/net/tun` (интерфейс жив, после `AwgTurnOff`
интерфейсов 0). Регрессионные тесты: `TestAwgFailureKeepsRecycledDescriptorUsable` (детерминированно
ловит «мину»: после GC слушатель на переиспользованном номере обязан принимать) и
`TestCloakForwardsAfterAwgAndXray` (отклонённая AWG-активация → Cloak получает тот же номер → в том
же процессе Xray → данные обязаны дойти). На неисправленном дереве оба падают, после фикса пара
тестов **30/30**, полный пакет `mobile` **30/30** (до фикса 15/30 fail).

**Xray-конфиг напрямую в protobuf (`internal/xrayclient/xrayconf.go`, 1581 строка).** Helper больше
не тянет `xray-core/infra/conf` и `main/json`: конфиг собирается в `core.Config` (порт нужных частей
conf — log/dispatcher, outbound, mux, stream, tcp/ws/grpc/httpupgrade/splithttp, tls/reality,
vless/vmess/trojan). Итог: `xio-tunnel.exe` **35 567 104 → 31 450 112 Б** (−4 116 992 Б, −11,58 %,
`.text` −1,81 МБ, `.rdata` −2,18 МБ), символов `infra/conf` 261 → 0, `main/json` 4 → 0, полностью
