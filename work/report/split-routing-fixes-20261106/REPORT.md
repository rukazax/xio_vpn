# Routing contract fixes — implementation candidate (not independent acceptance)

Base: `94fe32d1ecc5149bd5f7123edc2287248909d6a3`, dedicated branch `agent/split-routing-fixes-20261106`. Scope C3/C4/C8 only. Prior independent audit/evidence remains untouched outside this worktree.

## Design and compatibility contract

- Keep 64 DNS-lookups, 96 resolved-addresses and 128 combined native-network budgets. Exceeding a budget, empty/failed DNS or a partial bounded result is explicit incomplete policy and refuses activation in both IP modes; never install a silent subset. Explicit ipExclude rules retain their original direct/exclusion semantics. Wildcards remain apex + known direct children, not interception or exhaustive subdomain discovery.
- Cache success only after native apply completes and the Dart generation is still current. Failed nonempty apply and failed clear retry; a new owned native lease re-acknowledges even cached DNS results. Lifecycle revocation may retain a still-fresh successful DNS result, but never its native lease. DNS cache expiry is not extended by reapplication. Each application carries the remaining validForMillis; native receipt charges that bounded allowance from begin, including channel/lookup/write delay, rather than issuing ten fresh minutes to old cached DNS.
- DOWN, disposal, new admitted connect, expiry and policy edits revoke Dart generation before asynchronous continuation. A delayed begin reply is canceled against its exact revision+lease and never starts DNS. Old cleanup cannot cancel a new lease.
- Native policy revision is a persisted UUID (legacy policies are upgraded on first begin). Read/snapshot/begin, revision+lease check/write, and policy edits are synchronized on one per-policy gate. Writes require revision+lease, including clears; legacy unversioned writes fail closed rather than accepting potentially stale clears.
- Domain-bearing policies require a successful process-local resolution receipt younger than ten minutes. Persisted addresses alone do NOT authorize domain activation after process restart. Thus background tile/boot with domains after restart/receipt expiry requires opening the new app and resolving again. This intentional availability cost is not claimed seamless backward compatibility. App-only/IP-only policies continue without a domain receipt. No new TUN/IP-family/direct allowances.
- Native helper gate is separate from Engine/publication/TUN leases and desktop setup under parallel worker ownership. No edits to those sections, Go/mobile transport, settings, vault, website probe or release artifacts.

### Untested / acceptance boundary

No installs, phone, TUN, host routes, services, live DNS/HTTP probes, Windows executables, APK/JNI build, release artifact/signing or production assets changed. Original tracked assets were copied only for offline Flutter test loading, never executed or edited. Native Android policy wrapper/handler wiring is source-checked, not a full Android type/link/runtime acceptance. Wildcard support remains a finite declared expansion, not CDN interception or a universal no-leak guarantee. Conservative capacity admission may reject a redundant domain address also covered by a manual route; it does not silently omit required addresses. This candidate is ready for a separate independent review, not self-accepted or release-ready.
