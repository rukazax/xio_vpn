# P2: desktop AccountVault namespace mismatch

## Result and scope

Base: `3da0535d96b3c139ddad2b80b7fc8b457f30a6a6`; exclusive branch `agent/account-vault-fix-20261105` (initially clean). Production change is limited to [credentials.dart](../../../app/lib/credentials.dart). No AccountVault ID changes, migration, schema/UI/core/runtime/native/server/build metadata changes, asset regeneration, publication, release or integration claim. Parent independently reviews before integration. Commit identity is supplied in the handoff; `git log -1 --format=fuller` records UTC author/committer dates.

[AccountVault](../../../app/lib/account_access.dart#L68) generates `state` + 64 lowercase SHA256 hex characters. Its desktop write delegates to CredentialVault, whose baseline write accepted only `ssh|vpn` + 64 hex. The fresh import and existing-account update paths in [core.dart](../../../app/lib/core.dart#L1825) therefore throw before account storage. This is reproducible, not inferred solely from regex inspection.

The explicit `validateCredentialId(id, desktop: ...)` contract now permits only `ssh|vpn|state` + 64 lowercase hex on desktop, and the prior `ssh|vpn` contract on mobile. The same validator runs at the beginning of read/write/delete, before folder creation, file construction, serialization, crypto or channel calls. Full-match length is checked, rejecting trailing control characters as well as arbitrary prefixes, absolute paths, traversal, separators, uppercase and wrong lengths. Existing state filenames and envelope are unchanged; no material is renamed or regenerated by this change.

## Explicit boundaries and separate observations

- **Windows DPAPI was not executed.** SAC prevents unsigned runtime execution; no bypass attempted. Windows routes through the same validated Dart desktop boundary, and [windows_crypto.dart](../../../app/lib/windows_crypto.dart#L49) remains unchanged. Linux real execution plus pure namespace tests/source inspection are not Windows physical execution evidence.
- No Android/iOS device tests, complete app import UI E2E, native daemon, full suite, cross-process durability, crash/fsync-directory durability or release acceptance claim.
- Existing key creation has an `exists -> write` race for concurrent fresh writers; the fixed `$id.bin.tmp` name also admits concurrent writer collisions. These are **source observations**, not experimentally proven in this task, and remain out of scope. Native journal's in-process serialization is not a cross-process lock.
- Existing Linux `_desktopCrypt` creates a key when absent even on decrypt; missing-key recovery behavior is not changed or covered by the corruption test (which deliberately keeps an existing malformed key). A future vault durability/recovery task should assess it separately.
- All background jobs were collected; no app/server/service was started or left running by this task. Parent checkout/workers were not edited.
