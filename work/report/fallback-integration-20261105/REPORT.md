## Implemented, and deliberately not claimed

### Android

- Production `PublicationLease` is a pure short-held synchronized gate with TWO different identities: queued/permission admission captures the DOWN-generation; each successful begin validates that generation/budget/cancellation reservation and returns a NEW monotonically unique publication token. Internal child retirement invalidates only publication; external revoke advances the DOWN-generation, invalidates publication and cancels registered roots/descendants. Thus queued old UP cannot reuse a different owner's live budget, and legitimate new requests do not lose their own success by confusing admission with publication. The gate performs no JNI, status, fsync, TUN operation or physical teardown.
- Actual service notification DISCONNECT and onRevoke call `Engine.revokePublication()` synchronously before enqueueing physical `Engine.disconnect` on the same worker. The old onRevoke UI-thread preference commit is removed; durable wanted=false remains serialized worker work. This is immediate in-memory connection intent/publication revocation, not a claim that disk persistence finishes before return.
- Controller/tile DOWN similarly fences before the queue, including a second tile DOWN while a controller connect is busy. Activity roots are registered before permission/worker waiting. Their captured admission generation is used only at Engine admission; posted own success captures the unique publication token returned by Engine.connect. Controller roots are registered before worker waiting and released when the original round finishes.
- Internal failed-candidate retirement matches both round and exact child-budget identity, invalidates its callbacks and cancels only that child; external DOWN cancels all registered pending roots. Old cancellation/retirement cannot affect a new child even if the controller reuses the same round ID. The pure gate reserves an admitted native cancellation until its real owner returns, without holding the gate across JNI; replacement begin is rejected during that reservation. Original child-local assertions remain unchanged; new production-gate execution explicitly proves automatic second-candidate success on the SAME original 30s deadline.
- Worker cleanup after a failed/expired setup is now `disconnectOwned(roundId, exactChild, cleanupBudget)`, not unconditional global disconnect. Both foreground Activity catch and controller attempt/outer catch use that exact owner check; a queued15s A that expires before acquiring ownership cannot tear down a winning30s B. Same-round older-child cleanup is rejected, while actual matching-owner cleanup is still admitted. Explicit user/service DOWN remains intentionally global. This correction is source-wiring plus actual Java gate tabletop proof, not execution of physical Android cleanup.
- Rivet/Xray/OpenVPN actual TUN/admission/publication boundaries check their captured activation token and explicitly pass it to service UP publication; OpenVPN's Client/CONNECTED callback retains that token. AWG uses a per-activation Tunnel callback object, with a volatile current-tunnel handle, rejecting stale callbacks before active-ID/UI effects. Service stateChanged requires an explicit caller-owned token, not a global-token lookup. Controller expiry returns a retirement token captured under the exact cancel-owner gate and passes it to DOWN publication; new activation invalidates even a DOWN queued after native cancel joins. Native APIs already admitted before revocation may finish later; pure revocation never waits for them. Physical cleanup/reservation remains with the original serialized owner, not a replacement or fabricated success.
- This is production Java gate execution plus actual Kotlin source-entry/order verification, **not Kotlin/JNI/APK or phone lifecycle execution**. No old-JNI policy fallback was added.

### Desktop Linux / Windows

- One setup lease uses the original Runtime monotonic work deadline and generation, including time already spent queued/authorizing/cleaning. Per-operation caps are minima of remaining setup time, not fresh budgets.
- Runtime DOWN increments generation and cancels the exact pending setup under the same short gate used for per-effect admission. Each Linux command/plan step, physical DNS query and Windows native operation is separately admitted. Final current-session publication and setup detachment are atomic with that generation fence. The gate is never held across a blocking OS call.
- Context-aware endpoint preparation reaches actual physical resolution; canceled results do not publish cache entries or bypass routes. Context-insensitive legacy helper signatures remain only for inherited tests; the actual Runtime explicitly supplies the setup context/lease.
- AWG handshake admission recomputes remaining duration and receives the shared setup cancellation; native TUN/device/attach phases are separately admitted. Accepted mobile/internal-rivet/crypto/auth/parser/transport sources were not changed.
- Windows sharing setup is split into individually admitted script steps. The same owned selectors/receipt schema are retained; intended owned rule state is read and receipt journaled before the first rule effect. Each step revalidates the existing foreign-sharing checks. Cleanup runs under an independent bounded context even after setup cancellation. Actual rollback no longer swallows DisableSharing errors: it attempts both owned configurations, confirms disabled state before receipt deletion, propagates rule/receipt errors (missing rule alone is benign), and retains the receipt for unconfirmed cleanup. Normal owned disable also verifies disabled state. Joined-but-failed sharing cleanup keeps cleanupPending rather than acknowledging clean teardown.
- Linux cleanup has a separate bounded context, never the canceled setup context. Setup/teardown retains Runtime ownership until the actual call/cleanup joins; timed-out owners keep the original mutex reservation. Winner network admissions detach from setup cancellation; no HTTP/RPC request context becomes transport lifetime.
- Already-admitted synchronous native/kernel calls cannot be proven instantly canceled. These tests do not prove arbitrary Windows kernel/COM cancellation, foreign concurrent OS mutation, real routing, packaged behavior, or release readiness.
