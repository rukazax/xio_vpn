## Contract correction

- Native **DNS provenance** (resolution ID, revision, original monotonic expiry) is separate from **activation ownership** (current revision+lease+ready receipt). DOWN cancels ownership while preserving provenance; a new lease may reuse the same DNS origin only before that original expiry. Repeated writes under one lease also cannot extend the deadline.
- Native begin returns a resolution ID and reuseAllowed. For valid same-origin reuse, commit caps the allowance at the retained original deadline. A wall-clock-derived allowance can never extend that origin. Unknown/expired IDs, policy changes and process restart return a NEW ID with reuseAllowed=false; actual AppStore forces fresh DNS before applying that ID. Missing local cache and explicit force also request a new ID. Expired OLD identity cannot commit into the new candidate.
- Android expiry authority is explicitly `android.os.SystemClock.elapsedRealtime`, including deep sleep; the pure gate requires an injected clock. No System.nanoTime or Dart Stopwatch substitution. Dart Android cache reuse obeys native provenance rather than wall-clock age; standalone helper callers without native provenance retain their old wall-clock caching API, but that API cannot authorize Android activation.
- Native begin/revision validation/write/receipt commit remain synchronized on the same per-policy monitor; successful native apply plus post-await ownership still precedes Dart cache publication. No capacity, finite-wildcard, explicit-exclusion or IP-family policy relaxation.
- Domain-bearing tile/boot activation still requires a live native ready receipt; provenance alone is not activation permission. Policy edit/restart invalidates provenance. Empty-domain paths retain their previous behavior.
